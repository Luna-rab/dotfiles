合意に達するまで、ユーザーに 1 問ずつ質問して設計を詰める。

## 進め方

1. 質問する前に、コードベースと参照できる資料を調べる。調べればわかることは質問しない。
2. 質問は 1 つだけ出して、回答を待つ。複数をまとめて出さない。`AskUserQuestion` は使わず、下のフォーマットで本文に書く。
3. 回答が曖昧なとき、根拠が示されていないときは、次に進まず同じ論点を追撃する。
4. 幅より深さを優先する。1 つの論点から新しい発見が出なくなるまで掘ってから、次の論点へ移る。
5. 論点を掘り尽くしたら終了を提案する。ユーザーが続行を求めたら続ける。
6. ユーザーが合意を確認するまで、実装や変更に着手しない。

## 質問フォーマット

```
### Q<番号>: <質問文>

<この質問で何が決まるのか。調べた結果を、ファイル名・行番号・具体値で添える>

- **A** — <選択肢>
- **B** — <選択肢>

**推奨: A** — <理由>
```

選択肢を並べられない論点は、箇条書きを省いて自由回答で聞く。推奨と理由は省かない。

## 終了時のまとめフォーマット

```
## まとめ

### 決まったこと
- <論点>: <結論>（理由: <根拠>）

### 保留
- <論点>: <保留にした理由と、決めるために必要なもの>
```
