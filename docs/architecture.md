# 構成と変更手順

## 担当範囲

設定と導入処理をツール別にまとめる。dotfiles は個人環境を組み立て、agent-toolkit は
エージェント向けの機能と配置処理を提供する。各プロジェクト固有の規約はプロジェクト側に置く。
認証情報・履歴・ラン記録は各環境で保持する。

モデル・権限モード・プラグイン選択と VS Code の端末プロファイルは、現在は toolkit が配布する。
toolkit 側の選択導入が整った後に移す。先に同じ設定を dotfiles からも配布して上書きし合う状態にはしない。

## モジュールの追加

1. `modules/<名前>/files/` に配布物を置く。
2. 同じモジュールの `install.sh` に `install_<名前>` 関数を定義する。
3. 関数から `install_link <配布元> <配置先>` または `install_copy <配布元> <配置先>` を呼ぶ。
4. ルートの `install.sh` に明示的な読み込みと呼び出しを追加する。
5. README の一覧を更新する。

モジュールの読み込みだけでは副作用を起こさない。実行順序はルートだけが決める。
ファイル配置はネットワークより先に終え、外部ツールの導入処理は失敗を明示して呼び出し元へ返す。
共通関数の引数やコマンドへ渡すパスは引用し、空白を含む checkout を扱えるようにする。

## 配置の共通処理

`DOTFILES_ROOT` は実行中の checkout、`DOTFILES_TARGET_HOME` は通常設定の配置先。
標準では実ホームを使う。
バックアップは配置先からの相対パスと時刻を含み、同名があれば連番を付ける。
同じ配布元へのリンクや、同じ内容のコピーは変更しない。

ディレクトリ全体は配置せず、管理するファイルだけを指定する。ローカル設定や別ツールの配置物は残す。

## agent-toolkit との接続

dotfiles は git で必要な checkout を取得し、mise の環境から toolkit の `install.sh` を呼ぶ。
既存 checkout の更新、AI 設定のマージ、gh-stack・archify の取得処理は複製しない。
更新する場合は toolkit 側で `git pull --ff-only` と `./install.sh` を実行する。

toolkit の導入・配置インターフェースが変わったら、変更するのは agent-toolkit モジュールだけ。
通常設定の配置とシェル初期化へ toolkit の内部構造を持ち込まない。

## 配置先の指定

`DOTFILES_TARGET_HOME` を実ホーム以外にした場合、mise 本体のダウンロードと toolkit の起動を抑止する。
